Full System QA Error Log
Audit date: 2026-08-03

1. Dependency install blocker
Command:
  .\.venv\Scripts\python.exe -m pip install -r requirements.txt
Error:
  ERROR: Invalid requirement: '"""Python Dependencies"""'
Cause:
  `requirements.txt` line 1 was a Python docstring, not a pip comment.
Fix applied:
  Changed line 1 to `# Python Dependencies`.

2. Full requirements install timeout
Command:
  .\.venv\Scripts\python.exe -m pip install -r requirements.txt
Error:
  Command timed out after 15 minutes.
Impact:
  Full requirements file was not proven installable end to end in one run.
Workaround:
  Installed required runtime/test packages in chunks; `pip check` passed.

3. Package import failures
Commands:
  Import matrix for workload/carbon/job modules.
Error:
  Imports such as `from predictor import ...` and `from carbon_engine.config import ...` failed when modules were imported through the `src.*` package path.
Fix applied:
  Added relative imports with fallback in workload, carbon, and job engine modules.

4. Pandas 3 runtime adapter frequency error
Command:
  Engine 1 direct runtime adapter test.
Error:
  `Invalid frequency: 30S. Did you mean s?`
Fix applied:
  Changed resample frequency from uppercase `S` to lowercase `s`.

5. Pandas 3 `fillna(method=...)` error
Command:
  Engine 1 direct runtime adapter test.
Error:
  `NDFrame.fillna() got an unexpected keyword argument 'method'`
Fix applied:
  Replaced `fillna(method='ffill')` and `fillna(method='bfill')` with `.ffill()` and `.bfill()`.

6. Mock API mode originally skipped real LSTM model loading
Command:
  API startup and code inspection.
Problem:
  `LivePredictor` skipped model/scaler loading when `--mock` was used.
Impact:
  Required API test command would not use the real LSTM model.
Fix applied:
  Mock mode now affects metrics input only; real model/scaler are loaded.

7. Windows Unicode logging/output errors
Commands:
  API startup, `test_engine2_upgrade.py`, `test_engine3_implementation.py`, `decision_layer_validation.py`, `high_load_policy_fix_validation.py`, `verify_unified_dashboard.py`
Errors:
  `UnicodeEncodeError: 'charmap' codec can't encode character ...`
Cause:
  Windows console encoding was cp1252 and scripts/logging used checkmarks, crosses, and box-drawing characters.
Fix applied:
  Replaced Unicode arrows in core model/predictor logs. Reran standalone scripts with `PYTHONIOENCODING=utf-8`.
Remaining:
  Several validation scripts still require UTF-8 environment or ASCII output changes.

8. Runtime normalization warning
Command:
  Engine 1 direct runtime sequence test.
Error:
  `CPU normalization failed: X has 1 features, but MinMaxScaler is expecting 2 features as input.`
  `Memory normalization failed: X has 1 features, but MinMaxScaler is expecting 2 features as input.`
Cause:
  RuntimeAdapter was passed a two-feature scaler where it expects independent one-feature scalers.
Impact:
  Runtime sequence may fall back to raw, unnormalized values.
Status:
  Not fixed; needs a preprocessing correction.

9. Decision layer ignored Engine 2 selected pod count
Command:
  Real Engine 1/2/3 composed decision scenarios.
Problem:
  Decision layer fell back to `optimized_scenario.required_pods` and ignored top-level `optimized_required_pods`.
Impact:
  Final action could differ from Engine 2's selected recommendation.
Fix applied:
  `_extract_engine2_data` now reads top-level `optimized_required_pods` first.

10. Normal-load scale-up final pod bug

12. Prometheus CPU query incorrect
File:
  `src/workload_prediction_engine/metrics_collector.py`
Problem:
  Uses raw `container_cpu_usage_seconds_total{pod="..."}` cumulative counter.
Impact:
  CPU data is not suitable for CPU percent LSTM input.
Recommended fix:
  Use a rate query such as `sum(rate(container_cpu_usage_seconds_total{pod=~"...",container!="POD",image!=""}[1m])) * 100`, then normalize to the training CPU percentage basis.
